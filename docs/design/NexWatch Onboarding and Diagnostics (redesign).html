NexWatch: Onboarding + Diagnostics redesign

Redesign reference for the onboarding flow (:feature:onboarding) and the Diagnostics surface that replaces the raw text rows in WatchDebugScreen, redrawn in the established pattern: plain HTML/CSS against the exact :core:designsystem tokens, with the Part C motion system implemented live. Open it in a browser and interact with it. Translate into idiomatic Compose built on the theme, don't port the HTML structure literally.

  • Flow progress. A seven-step bar sits under the status bar on every onboarding screen, so a multi-step setup always says where you are and how much is left.
  • Permissions gate. Continue stays disabled until the four required permissions are granted, with one helper line naming what's missing. Location stays optional.
  • Find your watch gains a Bluetooth-off state alongside scanning and nothing-found.
  • Pairing runs its progress ring around the watch render and gains a failure state with retry paths.
  • Diagnostics becomes a real screen: connection state, per-day stat strip, event timeline, log preview, log export and background test. The timeline needs a new event log in DiagnosticsStore (today it keeps only last-* timestamps), so the events shown are illustrative sample data, not persisted values.

Onboarding and pairing

The seven-step setup as one flow. Every screen after Welcome carries the step bar. Interact with the controls: steppers, permission grants, the Bluetooth toggle, the pair-confirmation gate.
